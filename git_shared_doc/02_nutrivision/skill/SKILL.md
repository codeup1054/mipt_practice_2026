# nutriment-recognition — распознавание блюда

Скилл возвращает не свободный текст, а JSON, который можно сравнить между моделями.
Версия 2 добавляет проверку порции, аллергены и отказ, если блюдо не распознано.

## Когда использовать

- есть фото блюда и известен вес порции;
- нужно сравнить качество распознавания между моделями или чатами;
- нужны ингредиенты и КБЖУ в машинно-читаемом виде.

Не использовать: для медицинских рекомендаций, расчёта диеты и диагностики.

## Вход

```json
{"photo": "data/raw/dishes/greek_salad.jpg", "portion_weight_g": 250}
```

Если вес неизвестен, вернуть `error: "need_weight"` и попросить взвесить порцию.

## Выход

```json
{
  "components": [
    {"name": "помидоры", "weight_g": 100},
    {"name": "огурцы", "weight_g": 60},
    {"name": "фета", "weight_g": 40},
    {"name": "оливковое масло", "weight_g": 15}
  ],
  "kcal": 320,
  "protein": 11,
  "fat": 25,
  "carbs": 12,
  "confidence": 0.82,
  "notes": ["порция оценена по фото", "соус не виден"]
}
```

Обязательные поля: `components`, `kcal`, `protein`, `fat`, `carbs`, `confidence`,
`notes`. `components[]` — объекты `{name, weight_g}`.

## Правила

1. Не выдумывать ингредиенты, которых не видно. Сомнительное — в `notes`.
2. Сумма веса компонентов должна быть близка к весу порции; расхождение > 15 % — в `notes`.
3. Аллергены (орехи, молоко, глютен, яйца, рыба) указывать в `notes`, если видны или вероятны.
4. При нераспознанном блюде вернуть `{"error": "not_food", "notes": [...]}`.
5. При низкой уверенности — `{"error": "low_confidence", ...}`, а не случайные калории.
6. Не давать медицинских советов и не назначать питание.

## Проверка

- JSON проходит `validate_answer`;
- `0 <= confidence <= 1`;
- `kcal >= 0`, Б/Ж/У не отрицательные;
- у каждого компонента есть имя и вес;
- отказ не содержит выдуманных калорий.

## Версии

- v1 — свободный список ингредиентов и калории, без проверки порции.
- v2 — строгий JSON, отказ, аллергены, проверка суммы веса, CHANGELOG.
